# Automatic authorization

This topic describes how to create and manage automatic authorization rules.

## Background information

OceanBase Developer Center (ODC) allows system administrators to define automatic authorization rules. System administrators can create, modify, view, and disable automatic authorization rules.

The automatic authorization feature automatically grants roles or permissions to users whose names, departments, or login methods meet specific conditions when they are being created or log in for the first time, to avoid redundant authorization operations.

This topic describes how to create an automatic authorization rule named `grant system_admin for deptB`, which automatically grants the `system_admin` role to a user whose username in `memberOf.department` contains `deptB`.

## Create an automatic authorization rule

1. [Integrate OAuth 2.0 with ODC and authorize login to ODC](../../1000.system-integration/100.login-integration.md). Assume that the OAuth 2.0 system returns the following data structure:

    ```json
    {
      "id": 1,
      "name": "username",
      "mail": "example@email.com",
      "memberOf": {
        "department": [
          {
            "name": "deptA",
            "description": "this is a department"
          },
          {
            "name": "deptB",
            "description": "this is a department"
          }
        ],
        "extra": "some other info"
      }
    }
    ```

    You can use different expressions to obtain corresponding values from this data structure. The following table shows sample expressions and the corresponding values returned.

    | **<UI-TERM key="src.page.Project.Database.components.LogicDatabase.6483A6AD">Expression</UI-TERM>**   | **<UI-TERM key="odc.component.CommonTaskDetailModal.ExecutionResult">Result</UI-TERM>**           |
    |-------------|--------------|
    | id    | 1                    |
    | memberOf.department\[0\].name  |deptA   |
    | memberOf.department\[\*\].name |\["deptA", "deptB"\] |

2. Log in to Web ODC with a third-party account. In the left-side navigation pane of the project collaboration window, choose **<UI-TERM key="odc.components.FormResourceSelector.const.User">Users</UI-TERM>** > **<UI-TERM key="odc.page.Auth.AutomaticAuthorization">Automatic Authorization</UI-TERM>** > **<UI-TERM key="odc.components.AutoAuthPage.CreateARule">Create Rule</UI-TERM>**.

   <img src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/odc/433/700.database-change-management/100.user-permission-and-management/200.manage-automatic-authorization-rules/1EN.png" width="400">

3. Specify the following parameters in the **<UI-TERM key="odc.components.AutoAuthPage.CreateARule">Create Rule</UI-TERM>** panel.

   <img src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/odc/433/700.database-change-management/100.user-permission-and-management/200.manage-automatic-authorization-rules/2EN.png" width="900">

   | Parameter | Description |
   |--------|---------------|
   | Rule Name | The name of the rule, which must be unique. |
   | Status | Select **<UI-TERM key="odc.Env.components.InnerEnvironment.WhetherToEnable">Enabled</UI-TERM>** or **<UI-TERM key="odc.SensitiveRule.components.ViewSensitiveRuleDrawer.NotEnabled">Disabled</UI-TERM>**. <br> By default, the status of the rule is **<UI-TERM key="odc.CreateTable.TableConstraint.baseColumn.WhetherToEnable">Enabled</UI-TERM>**. You can set it to **<UI-TERM key="odc.SensitiveRule.components.ViewSensitiveRuleDrawer.NotEnabled">Disabled</UI-TERM>** as needed. A disabled rule cannot be accessed. |
   | Trigger Event | Select a trigger event. Only built-in events are available. Different events correspond to different trigger occasions. |
   | Matching Condition (Optional) | Click **<UI-TERM key="odc.NewSSODrawerButton.SSOForm.Add">Add</UI-TERM>** and specify the following four fields: <ul><li> **<UI-TERM key="odc.components.TypePage.Object">Object</UI-TERM>**: stores the trigger condition and the information required for executing the action. It can be a complex nested object such as an array, a list, or a map, or a simple object such as a string or a number. </li><li> **<UI-TERM key="src.page.Project.Database.components.LogicDatabase.B79AD693">Expression</UI-TERM>**: the index of the target in the object. Different types of objects use different indexing methods. </li><li> **<UI-TERM key="odc.components.AutoAuthPage.Operation">Operation</UI-TERM>**: the supported operation, such as "Contain", "Match", or "Equal". </li><li> **<UI-TERM key="odc.components.PLDebugResultSet.Value">Value</UI-TERM>**: the target value. <main id="notice" type='explain'><h4>Note</h4><ul><li>If you do not specify the matching condition, the action is unconditionally executed when the selected event is triggered. </li><li> If you select <strong>Match</strong> for the <strong>Operation</strong> field of the <strong>Matching Condition</strong> parameter, the value must be a regular expression. </li></ul></main>|
   | Actions (Optional) | Select **<UI-TERM key="odc.components.AutoAuthPage.GrantRoles">Grant Role</UI-TERM>** and/or **<UI-TERM key="odc.src.page.Auth.Autoauth.component.FormModal.AwardedProjectRole">Grant Project Roles</UI-TERM>** and specify the role name and/or project role name. <main id="notice" type='explain'><h4>Note</h4><p>If you do not specify the action, no action is executed regardless of whether the matching condition is met. </p></main> |
   | Remarks (Optional) | The description of the rule. |

4. After you specify the preceding information, click **<UI-TERM key="odc.components.CreateAsyncTaskModal.New">Create</UI-TERM>** in the lower-right corner of the panel.

5. After the rule is created, you can view the rule in the rule list.

## View automatic authorization rules

### Go to the list of automatic authorization rules

The following table describes the columns that provide information of automatic authorization rules in the list.

| Column | Description |
|--------|-----------|
| Rule Name | The name of the rule.  |
| Created By | The name of the user who created the rule. <br> You can click the search icon ![Search](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/odc/icon/search.jpg) to search for rules created by a specific user.  |
| Created At | The time when the rule was last edited. <br> You can sort rules in ascending or descending order of creation time.   |
| Enabling Status | The status of the rule. Valid values: **<UI-TERM key="odc.ExternalIntegration.SSO.WhetherToEnable">Enabled</UI-TERM>** and **<UI-TERM key="odc.component.DetailContent.NotEnabled">Disabled</UI-TERM>**. <br> You can click the filter icon ![Filter](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/odc/icon/filter.jpg) to filter rules by status. |
| Operation | You can view, edit, and delete rules. |


### View details of a rule

<img src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/odc/433/700.database-change-management/100.user-permission-and-management/200.manage-automatic-authorization-rules/4EN.png" width="400">

In the **<UI-TERM key="odc.components.AutoAuthPage.Operation">Operation</UI-TERM>** column, click **<UI-TERM key="odc.components.AutoAuthPage.View">View</UI-TERM>**. |--------|---------|

| Operation information | Displays information in fields such as **<UI-TERM key="odc.components.AutoAuthPage.component.Founder">Created By</UI-TERM>**, **<UI-TERM key="odc.components.RolePage.component.Created">Created At</UI-TERM>**, and **<UI-TERM key="odc.component.DetailContent.UpdateTime">Updated At</UI-TERM>**.  |

### Edit a rule

In the **<UI-TERM key="odc.components.AutoAuthPage.Operation">Operation</UI-TERM>** column, click **<UI-TERM key="odc.components.AutoAuthPage.Edit">Edit</UI-TERM>**. The **<UI-TERM key="odc.src.page.Secure.RiskLevel.components.EditRules">Edit Rule</UI-TERM>** panel appears.

The **<UI-TERM key="odc.src.page.Secure.RiskLevel.components.EditRules">Edit Rule</UI-TERM>** panel displays all the fields you specified when you created the rule. You can modify the fields as needed.

### Delete a rule

In the **<UI-TERM key="odc.components.AutoAuthPage.Operation">Operation</UI-TERM>** column, click **<UI-TERM key="odc.TablePage.Partitions.Delete">Delete</UI-TERM>** to delete an automatic authorization rule.
