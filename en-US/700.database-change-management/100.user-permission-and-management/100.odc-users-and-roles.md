# Users and roles

This topic introduces how to create and manage ODC users and roles.

## Background information

OceanBase Developer Center (ODC) allows users with the user creation permission to add users and grant permissions by using roles. The added users can log on to ODC by using their accounts and passwords.

A role is an object that holds user permissions, and users of the same role have the same permissions. ODC allows you to grant permissions to customized roles and assign the roles to users.


## Principle

In ODC, users, roles, projects, and system permissions are in the following relationships:

![1.20](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/odc/420/700.database-change-management/100.user-permission-and-management/100.odc-users-and-roles/1EN.png)

1. A user who has the user creation permission can create roles in **<UI-TERM key="odc.page.Auth.UserPermissions">User Permissions</UI-TERM>**.

2. A user who has the user creation permission can add users and grant role permissions to them in **<UI-TERM key="odc.page.Auth.UserPermissions">User Permissions</UI-TERM>**.

3. A user who has the review process operation permission add project roles to review nodes when creating review processes in **<UI-TERM key="odc.page.Secure.SafetySpecifications">Security Specifications</UI-TERM>**.

4. A user who has the risk level operation permission can select a review process when editing risk levels in **<UI-TERM key="odc.page.Secure.SafetySpecifications">Security Specifications</UI-TERM>**.

5. A user who has the risk identification permission can configure risk identification rules for specific risk levels in **<UI-TERM key="odc.page.Secure.SafetySpecifications">Security Specifications</UI-TERM>**.


## Considerations

- ODC has a built-in administrator user **<UI-TERM>admin</UI-TERM>**. This user automatically has the administrator role **<UI-TERM>system_admin</UI-TERM>**. The administrator role has all system permissions and has access to all public and individual resources. You cannot edit, delete, or disable the administrator role.

- A role is an object that holds user permissions, and users of the same role have the same permissions. ODC allows you to grant permissions to customized roles and assign the roles to users.

## Manage users

### Create a user

#### Create a single user

Assume that you want to create a user named `ODCUSER1` in ODC and grant the `system_admin` role permission to it as the administrator.

1. Log on to web ODC. In the left-side navigation pane, click **<UI-TERM key="odc.page.Auth.UserPermissions">User Permissions</UI-TERM>**.

2. On the **<UI-TERM key="odc.components.FormResourceSelector.const.User">Users</UI-TERM>** tab of the **<UI-TERM key="odc.page.Auth.UserPermissions">User Permissions</UI-TERM>** page, click **<UI-TERM key="odc.components.FormUserModal.CreateUser">Create User</UI-TERM>**, as shown in the preceding figure.

3. On the **<UI-TERM key="odc.components.FormUserModal.CreateUser">Create User</UI-TERM>** page, specify **<UI-TERM key="odc.components.FormUserModal.UserInformation">User Information</UI-TERM>**.


   - User information includes the following three parts:

      | Parameter | Description |
      |-------------|--------------|
      | Account | The account used to log on to ODC. You must specify a unique account containing 4 to 48 characters in length using letters, digits, and special characters. The supported special characters are `. _ + @ # $ %`  |
      | Name | The screen name to be displayed after the user logs on to ODC. The name must be specified and cannot exceed 110 characters in length.  |
      | Password | The password used to log on to ODC. The password must be specified. It must be 8 to 32 characters in length and contain at least two digits, two uppercase letters, two lowercase letters, and two special characters. The supported special characters are `. _ + @ # $ %` <br/>You can also click **<UI-TERM key="odc.components.FormUserModal.RandomPassword">Random Password</UI-TERM>** next to the field to generate a random password. <main id="notice" type='explain'><h4>Note</h4><p>After the administrator creates a new user or changes the password of a user, ODC prompts the user to change the user password to a complex one and protect the password against leakage when the user logs on for the first time. </p></main> |

   - ODC allows you to create multiple users at a time. You can click **<UI-TERM>+ Add User</UI-TERM>** to specify the information for multiple users.

2. Specify **<UI-TERM key="odc.components.FormUserModal.AccountStatus">Account Status</UI-TERM>**.

   By default, the new user is created in the **<UI-TERM key="odc.component.FormModal.Enable">Enable</UI-TERM>** status. You can manually disable it. A disabled account is unable to log on.

3. Assign roles to the new user.

   This parameter is optional. You can assign multiple roles to a user. Click the field. In the drop-down list, select the roles that you want to assign to all users you just added. If no role is available, go to the Create Role page to create one.

4. Specify **<UI-TERM key="odc.components.FormAutoAuthModal.Remarks">Remarks</UI-TERM>**

   This parameter is optional. Enter the description in the field. The remarks are optional and cannot exceed 140 characters in length.

5. Click **<UI-TERM key="odc.SensitiveRule.components.FormSensitiveRuleDrawer.Create">Create</UI-TERM>** to submit user information.

6. Save user information.


   In the **User Created** dialog box that appears after you click Create, you can view the information of all users you just created. In the dialog box, you can click **<UI-TERM key="odc.components.FormUserModal.CopyUserInformation">Copy User Information</UI-TERM>** and **<UI-TERM key="odc.components.FormUserModal.DownloadUserInformation">Download User Information</UI-TERM>** to save the information of multiple users in local storage.

   The two operations help you quickly save user information when you create multiple users at a time.

7. View the imported user information in the **<UI-TERM key="odc.components.FormResourceSelector.const.User">Users</UI-TERM>** list.


#### Import multiple users at a time

ODC V4.1.2 and later allow you to upload configuration files to batch import users. Perform the following steps:

1. On the **<UI-TERM key="odc.page.Auth.User">Users</UI-TERM>** tab of the **<UI-TERM key="odc.page.Auth.UserPermissions">User Permissions</UI-TERM>** page, click **<UI-TERM key="odc.src.component.AddDataSourceDropdown.BatchImport">Batch Import</UI-TERM>**.


2. In the **<UI-TERM key="odc.src.component.AddDataSourceDropdown.BatchImport">Batch Import</UI-TERM>** panel, click **<UI-TERM key="odc.component.BatchImportButton.modal.DownloadTemplate">Download Template</UI-TERM>**, and specify the parameters of the users to be imported.


   | Parameter | Description |
   |-------------|-------------------------|
   | Account | Required. The account used to log on to ODC. You must specify a unique account containing 4 to 48 characters in length using letters, digits, and special characters. The supported special characters are `. _ + @ # $ %`  |
   | Name | Required. The screen name to be displayed after the user logs on to ODC. The name cannot exceed 110 characters in length.  |
   | Password | Required. The password used to log on to ODC. The password must be 8 to 32 characters in length and contain at least two digits, two uppercase letters, two lowercase letters, and two special characters. The supported special characters are `. _ + @ # $ %`  |
   | Account Status | Required. Valid values: true and false.  |
   | Role | Optional. The name of the role created in ODC. Separate multiple role names with commas (,).  |
   | Remarks | Optional.  |


3. Click the file pool in the **<UI-TERM key="odc.src.component.AddDataSourceDropdown.BatchImport">Batch Import</UI-TERM>** panel to open the file explorer and select the file to be imported. You can also directly drag the file to the file pool to upload it.

4. Click **<UI-TERM key="odc.TreeNodeMenu.config.table.Import">Import</UI-TERM>**. After the users are imported, you can view them in the list of users.

### Edit User


1. In the user list, click **<UI-TERM key="odc.Script.Snippet.Edit">Edit</UI-TERM>** in the **<UI-TERM key="odc.component.RecordPopover.components.Actions">Actions</UI-TERM>** column.

2. In the **<UI-TERM key="odc.components.FormUserModal.EditUser">Edit User</UI-TERM>** panel, you can view all information specified when you create a user. After the user is created, the **<UI-TERM key="odc.components.FormRoleModal.component.Account">Account</UI-TERM>** cannot be modified. However, you can modify the **<UI-TERM>name</UI-TERM>**, **<UI-TERM>account status</UI-TERM>**, **<UI-TERM>roles</UI-TERM>**, and **<UI-TERM>remarks</UI-TERM>** and can change the **<UI-TERM>password</UI-TERM>** on the user details page.

## Manage roles

### Create a role

Assume that you want to create the `odc_project` role in ODC as the administrator. The role has permissions to edit the mysql_4.2.0 data source and manage the ODCUSER1 user.

1. In the left-side navigation pane of the project collaboration window, choose **<UI-TERM key="odc.page.Auth.UserPermissions">User Permissions</UI-TERM>** > **Roles** > **<UI-TERM key="odc.components.FormRoleModal.CreateARole">Create Role</UI-TERM>**.


2. In the **<UI-TERM key="odc.components.FormRoleModal.CreateARole">Create Role</UI-TERM>** panel, specify the following information.


   | Parameter | Description |
   |--------|------------|
   | Role Name | The role name must be specified and cannot exceed 48 characters in length.  |
   | Role Status | By default, the new role is created in the **<UI-TERM key="odc.Env.components.InnerEnvironment.WhetherToEnable">Enabled</UI-TERM>** status. You can specify the **<UI-TERM key="odc.SensitiveRule.components.ViewSensitiveRuleDrawer.NotEnabled">Disabled</UI-TERM>** status. The permissions for a disabled role do not take effect.  |
   | Permission Type | Select at least one permission type for the role. <br>ODC allows you to select **<UI-TERM key="odc.components.RolePage.component.ResourceManagementPermissions">Resource Management Permissions</UI-TERM>** and **<UI-TERM>System Operation Permissions</UI-TERM>**. After you select a permission type, the corresponding **<UI-TERM key="odc.components.FormRoleModal.component.PermissionSettings">Permission Settings</UI-TERM>** section appears below. When you create a role, you must specify and set at least one permission type for the role. <ul><li>Resource Management Permissions: the permissions to create, manage, edit, and view data sources, projects, roles, and users. </li><li>System Operation Permissions: the permissions to view and operate operation records, automatic authorization, review processes, risk identification rules, development specifications, and system integration. </li></ul> |
   | Remarks | Enter the description in the field. The remarks are optional and cannot exceed 140 characters in length.  |

3. After you specify the preceding information, click **<UI-TERM key="src.component.Task.LogicDatabaseAsyncTask.CreateModal.12C8523B">Create</UI-TERM>** in the lower-right corner of the panel to create a role.

4. After the role is created, you can view the role in the role list.

|--------|------------|

### View roles

1. In the role list, click **<UI-TERM key="odc.component.CommonTaskDetailModal.TaskRecord.View">View</UI-TERM>** in the **<UI-TERM key="odc.Env.components.InnerEnvironment.Operation">Actions</UI-TERM>** column.

2. In the **<UI-TERM key="odc.components.RolePage.RoleInformation">Role Information</UI-TERM>** panel, you can check the **<UI-TERM key="odc.components.RolePage.RoleDetails">Role Details</UI-TERM>** and **<UI-TERM key="odc.page.Auth.User">Users</UI-TERM>** tabs.


   | Tab | Description |
   |--------|----------|
   | Role Details | <ul><li> Role creation information: displays the information that you specified when you created the role in fields such as **<UI-TERM key="odc.components.RolePage.component.RoleName">Role Name</UI-TERM>**, **<UI-TERM key="odc.components.RolePage.component.PermissionType">Permission Type</UI-TERM>**, and **<UI-TERM key="odc.component.DetailContent.Remarks">Remarks</UI-TERM>**.  </li><li> Operation information: displays information in fields such as **<UI-TERM key="odc.components.AutoAuthPage.component.Founder">Created By</UI-TERM>**, **<UI-TERM key="odc.component.TaskDetailDrawer.TaskInfo.CreationTime">Created At</UI-TERM>**, and **<UI-TERM key="odc.components.UserPage.UpdateTime">Updated At</UI-TERM>**. </li><li> Role deletion: You can click **<UI-TERM key="odc.components.RecordPage.DeleteARole">Delete Role</UI-TERM>** in the lower part of the tab to delete the role. After the role is deleted, all data related to the role cannot be recovered, and the user permissions granted to the role are revoked. The user logon is not affected. </li></ul> |
   | Related User | The **<UI-TERM key="odc.components.RolePage.RelatedUsers">Related User</UI-TERM>** tab displays users that are granted the role. The user information is provided in the following columns: **<UI-TERM key="odc.component.Login.RegisterForm.Username">Username</UI-TERM>**, **<UI-TERM>Roles</UI-TERM>**, and **<UI-TERM key="odc.components.CompileResult.Status">Status</UI-TERM>**.  |

4. You can click **<UI-TERM key="odc.components.RolePage.CopyRoles">Copy Role</UI-TERM>** to go to the **<UI-TERM key="odc.components.FormRoleModal.CreateARole">Create Role</UI-TERM>** panel. In the panel that appears, the information of the current role is automatically filled.

### Edit a role

1. In the role list, click **<UI-TERM key="odc.ResourceTree.actions.Editing">Edit</UI-TERM>** in the **<UI-TERM key="odc.component.CommonTaskDetailModal.TaskRecord.Operation">Actions</UI-TERM>** column.

2. Modify the role information.

2. In the lower-right corner of the **<UI-TERM key="odc.components.FormRoleModal.EditARole">Edit Role</UI-TERM>** panel, click **<UI-TERM key="odc.components.FormAutoAuthModal.Save">Save</UI-TERM>** to save the changes.
