## Considerations

- Data sources

  - In ODC V4.2.0 and later, the concept of connection configuration is replaced with data source.

  - In ODC V4.2.0 and later, private connections are migrated to the individual workspace and exist as data sources.

  - In ODC V4.2.0 and later, public connections are migrated to the team workspace and exist as data sources.

  - In ODC V4.2.0 and later, for the read-only and read/write accounts in original public connections, only the read/write accounts are retained after the upgrade.

- User permissions

  - Starting from ODC V4.2.0, the `private_connection` and `apply_connection` roles are unavailable. In other words, the permissions of the two roles referenced by users no longer take effect after the upgrade to ODC V4.2.x.

  - Starting from ODC V4.2.0, the resource group feature is obsolete.

  - Starting from ODC V4.2.0, connection access permissions are obsolete. In ODC V4.2.x, database access control is implemented through project management.

- System settings

  - Starting from ODC V4.2.0, this feature is obsolete.

- Ticket module

  - Tickets initiated in versions earlier than ODC V4.2.0 can be viewed only on the **<UI-TERM key="odc.component.TaskPopover.IInitiated">Initiated by Me</UI-TERM>** tab.

- Partitioning plans

  - This feature is upgraded in ODC V4.2.0. After the upgrade to ODC V4.2.x, historical partitioning plans created in versions earlier than V4.2.0 will stop running.

- SQL plans

  - This feature is upgraded in ODC V4.2.0. After the upgrade to ODC V4.2.x, historical SQL plans created in versions earlier than V4.2.0 will stop running.

- Task process

  - Starting from ODC V4.2.0, this feature is obsolete. ODC V4.2.x provides the risk level module for equivalent effects.

- Data desensitization

  - This feature is upgraded in ODC V4.2.0. After the upgrade to ODC V4.2.x, the data desensitization configurations created in versions earlier than V4.2.0 no longer take effect.

- Session history

  - Starting from ODC V4.2.0, this feature is obsolete. In ODC V4.2.x, the usage status of an SQL window is saved by default.

## ODC V4.3.3

OceanBase Developer Center (ODC) V4.3.3 released in January 2025 enhances the following features:

- Data Archiving: This version offers a range of features to optimize the data archiving process, including support for archiving data from databases in CSV format to various object storage services such as Alibaba Cloud OSS, Tencent Cloud COS, Huawei Cloud OBS, and AWS S3. This version introduces the capability to configure archive tables in bulk, significantly enhancing the efficiency of configuring large-scale archiving tasks. ODC users are allowed to define dynamic target tables to meet the needs of storing historical data separately by day, month, or other periods. Additionally, the offset setting and calculation logic for custom variables have been improved for greater flexibility and accuracy.

- Project Management: Global project roles including Global Project Admin, Security Admin, and Global DBA have been introduced to address the issue of the platform manager's inability to effectively control all project resources. The management and viewing logic for tickets has been optimized, allowing administrators and DBAs to manage all tickets within a project, while project members can view all tickets within the project to ensure changes are controlled.

- Kernel Adaptation: To better support OceanBase, this version implements the management of external tables via GUI, adds functionality to display secondary partition information of partitioned tables, and adapts the ODP specified OBServer IP routing feature. Additionally, this version supports OceanBase V4.2.5, V4.3.3 versions, and the OBKV SQL mode.

For more information, see the **Feature updates** section.

### Version information

* **Current version**: V4.3.3

* **Previous version**: V4.3.2-BP3

* **Release date**: January 17, 2025

* **Supported upgrade path**: You can directly upgrade ODC V2.0.0 and later to this version.

### Feature updates

- Data Lifecycle Management

  - Added support for archiving data from databases to object storage. The object storage services supported in this version include Alibaba Cloud OSS, Tencent Cloud COS, Huawei Cloud OBS, and AWS S3. The archive files support the CSV format.

  - Added support for bulk configuration of archive tables, enhancing the efficiency of large-scale archiving task configuration.

  - Introduced dynamic target table definition to support storing historical data by day, month, or other time units.

  - Custom variables support setting an offset of 0, and the offset calculation logic has been optimized.

  - Optimized the anti-explosion logic for MySQL and Oracle databases to proactively throttle based on the proportion of active sessions.

  - Optimized rollback logic to only revert data archived in the current task.

  - Added support for editing history review with content comparison.

  - Added ability to delete archiving and cleanup tasks when completed or terminated.

- Project Management

  - Introduced global project roles including Global Project Admin, Global Security Admin, and Global DBA. The introduction of global project roles can address the pain point where platform leaders are unable to manage all project resources on the platform.

  - Added support for allowing users to remain in their most recently used project after logging out and logging back in, simplifying the user operation path.

  - Added support for saving project search criteria, reducing the need for frequent searches for high-frequency operation projects.

  - Added project archiving validation to check for unfinished tickets and periodic tasks before archiving.

  - Added support for project deletion for archived projects.

  - Implemented fine-grained view permission control with user-initiated permission requests.

- Tickets

  - Refined ticket management scope: admins and DBAs can manage all project tickets, while other roles can only manage self-initiated tickets. Also, all members can view tickets in their projects.

  - Extended "Create Again" functionality to all ticket types except logical database changes, partition plans, and shadow tables.

  - Added project column in non-project ticket module for quick project identification.

- SQL Development

  - Added GUI support for OceanBase external tables.

  - Added support for displaying secondary partitions in OceanBase partitioned tables.

  - Added support for editing stored procedures in OceanBase MySQL mode.

  - Enhanced connection keep-alive logic with 3-minute database request intervals.

- Security Specification

  - Expanded executable SQL types in SQL window to include `CALL`, `COMMENT`, `SET SESSION`, and more.

  - Extended SQL check support for native Oracle data sources.

  - Added change approval workflow for native Oracle data sources.

  - Standardized risk identification rule conditions using operators and English expressions to avoid ambiguity.

  - Added 2 new SQL check rules for standardizing `CREATE LIKE` and `CREATE AS` table creation statements.

- Online Schema Change

  - Added retry mechanism with enhanced retry logic for various failure scenarios.

  - Added status display for online schema changes, allowing progress tracking of running tasks.

- Other Enhancements

  - Added SAML single sign-on support.

  - Added session kill capability for native Oracle data sources.

  - Added compatibility for OceanBase V4.2.5 and V4.3.3.

  - Added support for OBKV SQL mode.

  - Added support for ODP to specify OBSERVER IP routing functionality.

  - Enabled secure cookie mechanism for enhanced data transmission security.

  - Added column width adjustment support for forms (ticket lists, database lists).

  - Clarify the "AND/OR" logic for multi-condition combinations in automatic authorization, ODC currently uses the "AND" logic.

### Known issues

* Client ODC cannot be installed in a directory whose name contains Chinese characters.

* The exported data file and content are incorrectly displayed when the table contains virtual columns.

* In Web ODC, the maximum size of schemas or data imported in a batch cannot exceed 2 GB. Otherwise, the upload cannot be performed.

* In Web ODC, the maximum size of schemas or data exported in a batch cannot exceed 2 GB. The excess part will be lost after the export.

* In the details of an export task, the total number of records of the exported objects is not accurate but depends on the views of OceanBase Database.

* If you do not set the `ob_enable_trace_log` parameter to `on`, only the execution plans of the SQL statements executed for the first time are displayed.
